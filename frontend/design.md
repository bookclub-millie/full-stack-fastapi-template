# 디자인 가이드

화면을 만들거나 수정할 때 따르는 프로젝트 공통 기준이다. 화면별 요구와 사용자 흐름은 [요구사항](../docs/prd.md)과 [사용자 경험](../docs/experience.md)에 기록한다.

## 디자인 방향

**중립적인 표면, 선명한 정보 계층, 붉은 주요 동작, 절제된 장식.**

- 사용자가 현재 상태와 다음 행동을 바로 알 수 있게 한다.
- 같은 의미에는 같은 컴포넌트·색상·용어를 사용한다.
- 정보와 작업을 먼저 배치한다. 강조·카드·일러스트에는 목적이 있어야 한다.
- 로딩·빈 결과·오류·권한 부족을 구분한다. 완료되지 않은 작업을 성공으로 표시하지 않는다.

## 기준 구현

값과 API는 아래 구현을 기준으로 한다. 이 문서에 토큰을 복제하거나 화면별 디자인 시스템을 만들지 않는다.

| 대상 | 기준 |
|---|---|
| 색상·간격·반경 | [KDS 토큰](../packages/ui/src/styles/tokens.css) |
| 의미 기반 별칭 | [공유 스타일](../packages/ui/src/styles/globals.css) |
| 기본 컴포넌트 | [@kds/ui](../packages/ui/src/components/) |
| 폰트 | [앱 스타일](src/index.css)의 Pretendard Variable 웹폰트 |
| 사용 예제 | [Storybook](src/stories/kds/) |

기존 토큰과 변형을 먼저 사용한다. 화면 하나를 맞추려고 원본 토큰을 수정하지 않는다. 반복되는 요구는 공유 계층에서 해결한다.

## 색상과 테마

| 역할 | 사용 |
|---|---|
| 기본 배경·표면 | `bg-background`, `bg-card` |
| 보조 표면 | `bg-muted` |
| 본문·보조 설명 | `text-foreground`, `text-muted-foreground` |
| 주요 동작 | 공유 Button의 기본 변형 |
| 경계 | `border-border`, `border-input` |
| 오류 | `text-destructive`와 오류 문구 |
| 포커스 | 공유 컴포넌트의 `focus-visible` 표시 |

- 임의의 HEX·RGB 색상을 화면에 추가하지 않는다.
- 주요 동작의 붉은색을 제목·아이콘·카드 전체에 반복하지 않는다.
- 상태를 색만으로 구분하지 않는다. 문구나 아이콘을 함께 제공한다.
- 서비스의 기본 스타일은 라이트다. 별도 테마가 필요한 화면은 기존 [ThemeProvider](src/components/theme-provider.tsx)를 따르며 배경·전경·hover·포커스를 각 테마에서 확인한다.
- 이미지 원본의 고유 색상은 유지할 수 있지만 주변 UI와의 식별성은 확인한다.

## 글자와 문구

- 공통 Pretendard Variable 웹폰트를 사용한다. 화면마다 별도 폰트를 추가하지 않는다.
- 본문과 주요 입력은 16px, 보조 설명은 14px를 기준으로 한다.
- 제목은 내용의 계층에 맞게 구분한다. 모든 영역을 크고 굵게 강조하지 않는다.
- 제목 태그의 의미와 순서를 유지하고, 긴 본문은 읽기 쉬운 줄 길이를 확보한다.
- 버튼에는 수행할 동작을 쓴다. 삭제 버튼은 “확인” 대신 대상과 동작을 밝힌다.
- 오류는 원인과 다음 행동을 설명한다. 실제 기능·보안·성과에 없는 내용을 주장하지 않는다.
- 화면 문구의 기본 언어는 한국어다. 같은 개념의 명칭과 표기 언어를 유지한다.

## 배치와 형태

- 간격은 4px 배수를 기준으로 8·12·16·24·32·48·64px를 우선 사용한다. 기존 컴포넌트의 세부 간격은 유지한다.
- 같은 작업의 요소는 가깝게, 다른 정보 그룹은 여백으로 구분한다.
- 짧은 폼을 화면 전체로 늘리거나 복잡한 표를 좁은 카드에 가두지 않는다.
- 기존 [인증 레이아웃](src/components/common/auth-layout.tsx)과 [서비스 레이아웃](src/routes/_layout.tsx)을 먼저 활용한다.
- 카드와 구분선은 실제 정보 그룹에만 사용한다. 불필요한 카드 중첩을 피한다.
- 반경·경계·그림자는 공유 컴포넌트 기본값을 따른다. 강한 그림자·그라데이션·유리 효과를 임의로 추가하지 않는다.
- 작은 화면에서는 열과 보조 영역을 재배치한다. 긴 표는 해당 영역에서 스크롤하고, 페이지 전체의 가로 넘침은 피한다.
- 고정 높이나 넘침 숨김으로 콘텐츠를 가리지 않는다. 긴 문구·확대·작은 화면 높이에서도 핵심 작업이 가능해야 한다.
- 이미지와 비동기 콘텐츠의 공간을 확보해 레이아웃 이동을 줄인다.

## 컴포넌트와 폼

- 새 기본 요소는 `@kds/ui`를 우선 사용한다. 기존 로컬 컴포넌트와 합성 API가 다를 수 있으므로 사용 예제를 확인한다.
- 주요 동작은 명확히 강조하고 보조 동작은 낮은 강도의 변형을 사용한다.
- 배치·너비는 호출부에서 조절하고, 공통 색상·반경·포커스 변경은 공유 변형에서 해결한다.
- 이동에는 링크, 동작에는 버튼을 사용한다. 클릭 가능한 `div`로 대체하지 않는다.
- 입력에는 보이는 라벨을 제공한다. 플레이스홀더는 라벨을 대신하지 않는다.
- 입력 전에 필수 여부·형식·제약을 알리고 적절한 입력 타입·자동완성·모바일 키보드를 사용한다.
- 붙여넣기·자동완성·비밀번호 관리자를 막지 않는다. 재렌더링이나 실패로 입력값과 포커스를 잃지 않게 한다.
- 오류를 해당 입력과 연결하고 첫 오류로 이동할 수 있게 한다.
- Enter 제출·textarea 줄바꿈을 보존하고, IME 조합 중 Enter를 제출로 처리하지 않는다.
- 되돌릴 수 없는 동작은 대상·결과를 밝히고 확인 또는 실제 가능한 실행 취소를 제공한다.

## 상태와 피드백

| 상태 | 기준 |
|---|---|
| 로딩 | 원래 버튼 라벨을 유지하고 진행 상태를 알린다. 중복 제출을 막고 레이아웃 이동을 줄인다. |
| 빈 상태 | 데이터 없음과 검색 결과 없음을 구분하고 다음 행동을 제시한다. |
| 성공 | 실제 완료 뒤 결과를 알린다. 중요한 결과를 토스트에만 의존하지 않는다. |
| 오류 | 입력값을 보존하고 원인·복구 방법을 제공한다. 내부 오류·비밀정보를 노출하지 않는다. |
| 권한 부족 | 빈 목록으로 위장하지 않는다. 허용된 이동·복구 경로를 안내한다. |
| 비활성 | 사용할 수 없는 이유와 다시 사용할 수 있는 조건을 설명한다. |

입력이나 영역에 연결된 피드백은 인라인으로, 일시적 피드백은 토스트로 제공한다. 같은 결과를 여러 알림으로 중복 전달하지 않는다.

## 접근성

- 핵심 흐름을 키보드로 수행할 수 있어야 한다. 포커스 순서는 자연스럽고 표시가 가려지지 않아야 한다.
- 다이얼로그는 열 때 포커스 이동, 내부 순환, Escape 닫기, 닫힌 뒤 호출부 복귀를 확인한다. 모달은 중첩하지 않는다.
- 아이콘 단독 버튼에는 접근 가능한 이름을 제공한다. 툴팁이 이름이나 필수 설명을 대신하지 않는다.
- 중요한 비동기 상태 변화는 보조 기술에도 전달한다.
- 모바일 주요 동작의 클릭 영역은 최소 44×44px로 확보한다. 공유 Button·Input의 기본 높이는 36px이므로 그대로 충족한다고 가정하지 않는다.
- 모바일 입력 글자는 16px 이상으로 유지하고 브라우저 확대를 막지 않는다.
- 일반 텍스트 대비는 4.5:1, 큰 텍스트와 식별에 필요한 UI 경계·상태는 3:1 이상을 확보한다.
- 의미 있는 이미지는 대체 텍스트, 장식 이미지는 빈 대체 텍스트를 사용한다. 원본 비율과 라이선스를 지킨다.
- `prefers-reduced-motion`을 존중한다. 불필요한 이동·자동 스크롤·장식 애니메이션을 줄인다.

## 변경 후 확인

이 문서는 구현 기준이지 모든 화면이 충족한다는 인증이 아니다.

- 라이트·다크, 320px·390px·데스크톱, 200% 확대에서 핵심 작업을 확인한다.
- 정상 화면뿐 아니라 로딩·빈 상태·오류·권한 부족과 복구 동작을 확인한다.
- 키보드 이동·제출·다이얼로그 닫기·포커스 복귀를 실제 페이지에서 확인한다.
- 공통 컴포넌트 변경은 Storybook의 관련 상태에 반영한다. 실행 명령과 자동 검사 범위는 [README](README.md#frontend-quality)를 따른다.
- 자동 검사 통과와 실제 화면 검증을 구분한다. 실패를 없애려고 테스트나 기준 이미지를 변경하지 않는다.
- 맥락이 필요한 판단은 이 문서에, 기계적으로 판별할 규칙은 자동 검사에 반영한다. 반복되는 리뷰 피드백은 근거를 확인한 뒤 해당 기준을 갱신한다.

# 친근한 한국어 UX 라이팅

기능을 설명하는 시스템보다, 반갑게 맞아주고 다음 일을 도와주는 사람처럼 쓴다.
친근함은 마지막에 더하는 장식이 아니라 기본 목소리다. 문장 끝을 `~해요`로 바꾸는 것만으로는 부족하다.
Discord의 환영·공감 방식에서 영감을 받되 브랜드 고유 표현, 세계관, 번역투는 복제하지 않는다.

## 기본 결정

- **제목은 사람에게 말한다.** 로그인에는 `다시 만나 반가워요`, 첫 방문에는 `만나서 반가워요!`처럼 상황에 맞게 인사한다. 기존 환영 인사를 명확성·간결성만을 이유로 `로그인` 같은 기능명으로 되돌리지 않는다.
- **설명은 옆에서 돕듯 쓴다.** `이메일을 입력해 주세요`라는 지시만 반복하지 말고, 필요한 이유나 다음에 일어날 일을 자연스럽게 연결한다.
- **버튼은 행동을 말한다.** 제목이 다정해도 버튼은 `로그인`, `계정 만들기`, `이메일로 링크 받기`처럼 결과를 예측할 수 있어야 한다.
- **친근함을 길이와 바꾸지 않는다.** 라벨·버튼으로 충분한 입력 절차를 본문에서 다시 설명하지 않는다. 필요한 정보 없이 인사말만 늘리지도 않는다.
- **실패에는 도움을, 위험에는 정확한 사실을 준다.** 일상적인 실수에는 가볍게 공감하되 결제 실패·보안 사고·데이터 손실을 농담이나 `괜찮아요`로 덮지 않는다.

## 말투 기준

자연스러운 해요체, 따뜻한 환영, 부담 없는 제안이 기본이다. 밝은 환영·축하에는 느낌표를 쓸 수 있다.
반말, 억지 유행어, 과한 감탄, 모든 문장에 붙이는 `~드릴게요`는 피한다.
법적 고지·인용·확정 정책은 원래 의미와 필요한 격식을 유지한다.

| 피할 기본값 | 지향하는 표현 |
|---|---|
| 회원가입 / 로그인에 사용할 이메일과 비밀번호를 정해 주세요. | 만나서 반가워요! / 계정을 만들고 함께 시작해요. |
| 비밀번호 재설정 안내 | 비밀번호가 기억나지 않나요? |
| 재설정 링크 보내기 | 이메일로 링크 받기 |

위 문구는 자체 작성 예시다. Discord의 공식 한국어 문구나 모든 화면의 고정 답안이 아니다.

## 정확성의 경계

따뜻하게 바꾸되 기능·현재 상태·사용자 선택·불리한 정보는 바꾸지 않는다.
숫자·날짜·가격·정책·오류 코드·보간 변수·번역 키·접근성 연결·검증 조건을 보존한다.
API 응답·사용자 작성 콘텐츠·런타임 데이터는 문구 작업으로 치환하지 않는다.
접수를 완료로, 계정 존재를 숨기는 응답을 가입 확인으로 바꾸지 않는다.
구현되지 않은 재시도·문의·실행 취소나 확인하지 않은 안전·복구 시점을 약속하지 않는다.

## 작업 순서

1. 요청 범위의 화면·상태·사용자 행동을 확인한다. 기존 용어와 사용자가 직접 고른 문구는 존중하되, 말투 재작성 요청에서 기존의 딱딱함까지 답습하지 않는다.
2. [보이스와 톤](references/voice-tone.md)을 읽고, 필요한 경우 [컴포넌트](references/components.md)·[문장 패턴](references/patterns.md)·[표기법](references/style.md)을 참조한다.
3. 제목·설명·버튼을 한 묶음으로 쓴다. 제목의 감정과 설명의 도움, 버튼의 실제 행동이 이어지는지 판단한다.
4. 요청이 제안이면 문구만 제안한다. 적용 요청이면 사용자에게 보이는 텍스트·속성만 수정한다. 식별자·스타일·UI 구조·동작은 건드리지 않는다.
5. 한 번 묶어서 읽으며 어색한 말투·중복·정보 누락·보호 값 변경을 확인한다. 문구마다 테스트나 브라우저를 돌리지 않는다. 실제 잘림 문제가 있거나 사용자가 화면 검증을 요청한 경우에만 해당 화면을 확인한다.
6. 바뀐 방향과 대표 문구를 짧게 보고한다. 실행하지 않은 검증은 주장하지 않는다.

## 조사 근거

Discord 공식 자료에서 관찰한 표현과 이 프로젝트용 해석은 [보이스와 톤의 조사 근거](references/voice-tone.md#조사-근거)에 구분해 둔다.
출처를 매번 다시 조사하거나 화면 문구에 브랜드 이름을 넣을 필요는 없다.

# 문장 패턴

자체 작성 예시다. 그대로 복사하는 고정 문구가 아니라 상황·기능에 맞춰 고르는 기준이다.
사용자가 직접 고른 표현은 존중하고, 실제 상태·조건이 맞을 때만 적용한다.

## 인증 화면

| 화면 | 제목 | 설명 | 버튼 |
|---|---|---|---|
| 로그인 | 다시 만나 반가워요 | 이어서 함께해요. | 로그인 |
| 회원가입 | 만나서 반가워요! | 계정을 만들고 함께 시작해요. | 계정 만들기 |
| 비밀번호 찾기 | 비밀번호가 기억나지 않나요? | 괜찮아요. 가입한 이메일을 알려주시면 새 비밀번호를 만들 수 있는 링크를 보내드릴게요. | 이메일로 링크 받기 |
| 비밀번호 재설정 | 새 비밀번호를 정해 볼까요? | 앞으로 로그인할 때 쓸 비밀번호예요. | 비밀번호 바꾸기 |

로그인처럼 입력 라벨과 버튼만으로 충분한 화면은 설명을 꼭 추가할 필요가 없다.
문구 적용 요청에서 기존 설명 영역을 없애는 구조 변경까지 하지는 않는다.
인증 방식·가입 정책이 위 예시와 다르면 실제 흐름에 맞게 쓴다.

## 상태별 문구

| 상황 | 예시 | 적용 조건 |
|---|---|---|
| 첫 항목 없음 | `아직 만든 항목이 없어요. 첫 항목을 만들어 볼까요?` | 조회 성공, 생성 기능 제공 |
| 검색 결과 없음 | `찾는 결과가 없네요. 다른 검색어로 찾아볼까요?` | 검색 성공, 검색어 변경 가능 |
| 저장 완료 | `저장했어요.` | 실제 저장 성공 |
| 비밀번호 변경 완료 | `비밀번호를 바꿨어요. 새 비밀번호로 로그인해 주세요.` | 변경 성공, 다음 단계가 로그인 |
| 복구 요청 접수 | `이메일을 확인해 주세요.` / `가입된 이메일 주소라면 비밀번호를 바꿀 수 있는 링크를 보내드릴게요.` | 계정 존재를 숨기는 응답, 가입 계정에는 이메일 발송 처리 |
| 입력 형식 오류 | `이메일 주소를 다시 확인해 주세요.` | 이메일 형식 검증 실패 |
| 비밀번호 불일치 | `비밀번호가 서로 달라요. 다시 확인해 주세요.` | 비밀번호 확인 필드와 불일치 |
| 로그인 실패 | `로그인하지 못했어요. 이메일과 비밀번호를 다시 확인해 주세요.` | 자격 증명 거부. 연결 실패에 쓰지 않음 |
| 처리 중 | `저장하고 있어요.` | 저장 완료 전 |
| 조회 실패 | `목록을 불러오지 못했어요. 다시 시도해 주세요.` | 실패 확인, 재시도 가능 |
| 영구 삭제 확인 | `항목을 삭제할까요?` / `삭제하면 되돌릴 수 없어요.` | 실제로 복구 불가능한 삭제 |

`괜찮아요`, `반가워요`, `~볼까요?`를 모든 상태에 끼워 넣지 않는다.
친근함은 상황에 맞는 태도이지 특정 단어의 반복이 아니다.

## 변수와 사실

- 기존 보간 문법·변수명·오류 코드는 보존한다.
- 받침에 맞춰 조사를 고른다. 동적 조사를 처리할 기존 기능이 없으면 조사가 필요 없는 문장으로 쓴다. 문구 작업에 새 로직을 끼워 넣지 않는다.
- 권한 부족·세션 만료·연결 실패·서버 오류를 같은 원인으로 단정하지 않는다.
- 지원 경로·실행 취소·재시도는 실제 기능이 있을 때만 안내한다.
- 저장·발송·삭제의 접수와 완료를 구분한다. 확인되지 않은 도착·복구 시간은 약속하지 않는다.

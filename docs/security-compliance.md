# 보안 준수

정해진 보안 기준을 어떻게 지켰는지 기록한다. 정책별 적용 여부와 이유·코드 위치를 적고, 시험 후 정상·거부 결과와 제약을 연결한다.

## 적용 기준

- 정책·기준 출처와 버전:
- 검토일:
- 적용 범위:
- 검토 담당자:

적용 기준은 별도 정책 원문을 따른다. `security-policy.md`가 제공되면 내용을 임의로 변경하지 않고 출처·버전·적용 범위를 확인한다. 현재 정책 원문은 등록되지 않았다. 이 문서는 정책을 새로 정하는 문서가 아니라 적용·검증 결과를 기록하는 문서다.

## 항목별 확인 내용

아래는 참고 출처의 보안 항목 요약이다. 구체적인 적용 범위·수치·방식은 정책 원문에 따라 확인한다.

| SEC | 확인할 내용 |
|---|---|
| SEC-01 | 키·토큰·비밀번호를 코드·URL·로그에 노출하지 않는다. 실제 비밀 대신 환경변수 예시와 안전한 설정 방법을 기록한다. |
| SEC-02 | 인증이 필요한 기능은 서버에서 확인한다. 화면에서 버튼을 숨기는 것으로 인증을 대신하지 않는다. |
| SEC-03 | 다른 사용자·팀의 자료를 직접 요청해도 읽거나 바꿀 수 없는지 확인한다. 역할과 자료 소유권을 함께 검증한다. |
| SEC-04 | 잘못되거나 과도한 입력을 서버에서 처리한다. 입력 경계와 실패 결과를 시험으로 남긴다. |
| SEC-05 | 직접 비밀번호를 저장한다면 정책에 맞는 안전한 저장 방식을 사용한다. 해당 없으면 이유를 남긴다. |
| SEC-06 | 외부 연결은 보안 전송을 사용하고 필요한 정보만 전달한다. 정확한 적용 기준은 정책 원문에서 확인한다. |
| SEC-07 | API 응답과 화면에 불필요한 개인정보를 남기지 않는다. 서버 응답을 직접 확인하고 필요한 마스킹을 검증한다. |
| SEC-08 | 인증 정보의 발급·관리를 확인하고 만료·로그아웃 후 재사용이 거부되는지 검증한다. |
| SEC-09 | 로그인 반복 실패와 과도한 요청의 제한·복구를 확인한다. 횟수·대기 시간은 적용 정책을 따른다. |
| SEC-10 | 로그인 실패·권한 변경 등 중요한 사건을 추적할 수 있게 기록한다. 감사 기록에도 비밀정보를 넣지 않는다. |
| SEC-11 | 개발·시험·운영 설정을 구분한다. 샘플 계정·디버그 설정이 의도하지 않은 환경에 남지 않는지 확인한다. |
| SEC-12 | 미적용 사유·위험·대안을 적는다. 미확인은 미검증, 승인받지 않은 예외는 대기로 표시한다. |

서비스에 해당하지 않는 기능은 억지로 추가하지 않고 적용 제외 사유를 기록한다.

미실행은 미검증, 해당 없음은 사유를 기록한다. 키·토큰·비밀번호는 코드·URL·로그·문서에 노출하지 않는다. 실제 비밀 대신 환경변수 예시와 안전한 설정 방법을 적는다.

자료 권한이 적용되는 경우에는 본인 조회 성공 / 타인 요청 거부 / 자료 유출 없음 / 저장값 불변을 각각 TC와 실행 근거로 연결한다. 이는 작성 기준이며 현재 구현이나 검증 결과가 아니다.

# 개발 과정

AI와 함께 어떻게 개발했는지 기록한다. 작업·리뷰 직후 팀원별 역할과 AI 활용·검증 과정을 실제 근거로 남긴다. 실행 방법은 [로컬 개발 안내](local-development.md)를 참고한다.

## 작업·리뷰 방식
<!-- Issue 관리, 역할 분담, 브랜치·PR·리뷰·완료 판단 방식을 작성한다. -->

기본 흐름은 [ADR-001](adr/001-openspec-docs-traceability.md)을 따른다.

1. `/opsx:propose`로 변경을 제안하고 제안(spec) PR을 리뷰해 머지한다. 머지되면 개발 작업 Issue가 자동으로 만들어진다.
2. 브랜치에서 구현하고 PR을 연다. Harness Gate·테스트와 작성자가 아닌 팀원 1명의 승인을 받아 머지한다([CI 하네스](ci-harness.md)).
3. `/opsx:archive`로 마무리하는 PR에 문서 결과와 아래 "AI 활용과 검증" 행을 함께 넣는다. 머지되면 Issue가 근거와 함께 완료로 닫힌다.

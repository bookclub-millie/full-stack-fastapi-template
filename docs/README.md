## 작성 원칙

- 요구(REQ) → 인수조건(AC) → Issue·코드 → 테스트(TC) → 실제 결과를 연결한다.
- 정상·오류·빈 상태·권한·복구 흐름을 필요한 범위에서 기록한다.
- 결과에는 실행 환경·소스 SHA·시각·근거 경로를 적는다. 실행하지 않았으면 미검증으로 남긴다.
- 보안 기준은 주최 측 원문을 따른다. 적용 제외·예외에는 이유와 검토 상태를 적는다.
- 현재 파일명을 유지한다. 공식 안내의 `security-compliance.md`, `e2e-test.md` 역할은 각각 `security.md`, `test.md`에 작성한다. 제출 파일명과 추가 문서 필요 여부는 최신 안내로 확인한다.
